# Статистика и диагностика пилота

16 ноября 2026, МСК. Публичная игра сохраняет существующие правила и профили. Статистика начинается после включения этой версии; прежние входы не реконструируются.

## Доступ владельца

Страница `/pilot`, API `/api/pilot`. В браузере нужно войти через ChatGPT аккаунтом владельца сайта. В игре ссылка появляется только после серверного разрешения. Telegram-подпись не предоставляет административных прав.

В Sites runtime настраиваются `PILOT_METRICS_ENABLED` (включено при значении `1`) и `PILOT_ADMIN_EMAIL` (проверенный аккаунт владельца, хранить как секрет). Код сравнивает серверный доверенный заголовок email и требует непустой authenticated user ID. Query-параметры, тело, cookie и Telegram не могут назначить владельца. Sites dispatch должен снимать пользовательские копии доверенных identity-заголовков и внедрять проверенные значения, как для существующей браузерной авторизации игры. При отсутствии настройки доступ закрыт. Значения не попадают в исходники, клиентскую сборку или архив.

API возвращает только агрегаты и номера диагностических запросов, без идентификаторов профилей, email, Telegram initData и игрового состояния. Ответы не кешируются. Фильтры ограничены 7/14/30 днями и каналами Telegram/браузер. Браузерный тест не смешивается с Telegram.

## Подсчёт

`pilot_profiles` хранит внутреннюю ссылку на игровой профиль, дату первого наблюдения и признак нового профиля из результата INSERT в players. Старые профили считаются существующими. Если параллельный повтор завершил наблюдение раньше создавшего профиль запроса, последующий подтверждённый признак нового профиля сохраняется; первые даты выбираются минимальными.

`pilot_visits` содержит одну запись на профиль и московский день. Это обращение к API игры после входа, включая обновление открытого приложения, а не доказательство активного нажатия кнопок. Валидный диагностический запрос также может создать первое наблюдение. Недействительная авторизация не создаёт посещений.

Первые выбор, игра, подарок и второй друг вычисляются по существующим подтверждённым квитанциям `operations` только для новой когорты. Повторы ключа не добавляют достижения, обучение не выдаёт дополнительных достижений само по себе. Успешный наградной раунд светлячков считается игрой; раунд без попаданий и локальная тренировка не считаются. Показатели независимы: игрок может получить подарок до первой игры.

Возвращение D1 — посещение именно следующего московского календарного дня после первого наблюдения. Это может быть менее 24 часов. Новые профили сегодняшнего дня исключены из знаменателя; если подходящих профилей ещё нет, процент `null`, UI показывает ожидание данных. Старые профили не попадают в новую когорту. Если первый сбор телеметрии не сработал, профиль может попасть в существующие при следующем входе; отсутствие наблюдений не заменяется оценками.

## Диагностика

Ошибки игрового HTTP API получают случайный request ID, одинаковый в заголовке и ответе. Собственные серверные журналы содержат только маршрут, код, статус и request ID. Произвольные provider exception messages, тела, identity-заголовки и ключи операций не логируются.

Авторизованный `/api/diagnostics` принимает только код из фиксированного списка и UUID события. Нужны тот же Origin и JSON не более 512 символов; посторонние поля отклоняются. Список: SDK недоступен, сетевой таймаут/сбой, неполный ответ сервера, ошибка загрузки иллюстрации. В D1 также попадают серверные `unavailable`/`busy` после подтверждения личности. Ошибки до входа доступны только в безопасном серверном журнале.

Повторы UUID не добавляют записи. INSERT со счётчиком в одном SQL ограничивает диагностику 20 записями на профиль и московский день даже при конкуренции. Клиентская очередь хранится только в памяти страницы, максимум 10 событий, отправляется с таймаутом 2,5 секунды и повторяется при восстановлении соединения или успешном обращении к игре. Авторизация передаётся только заголовком запроса; она не хранится в очереди/таблице диагностики и не входит в копируемый текст. Ошибки загрузки иллюстрации не содержат URL.

В игровом сообщении ошибки можно раскрыть «Диагностика для поддержки» и скопировать код, request ID, версию, канал и доступность SDK. Отправка кому-либо не автоматическая. При отсутствии clipboard API текст можно выделить вручную.

Диагностика может не дойти при отсутствии связи, истёкшем входе, закрытии страницы или достигнутом лимите. Клиентские сообщения — сигналы устройства, не доказательства серверного сбоя. Нулевой счётчик не означает отсутствие ошибок. Телеметрия не меняет транзакции наград и её ошибка не отменяет сохранённое действие.

## Хранение и миграция

`0001_milky_adam_warlock.sql` добавляет только три pilot-таблицы и их индексы. Существующие players/operations, исходная миграция и квитанции не меняются. Новые миграция, snapshot и journal сгенерированы Drizzle. В тестах применяется весь каталог SQL, включая исходную миграцию.

При чтении владельцем сводки подробности посещений и диагностики старше 35 дней удаляются. Карточка первого наблюдения остаётся; игровые квитанции и состояние не очищаются. В архивы входят только код/схема/сборка, не live D1, не наблюдения и не секретные runtime значения. `.env.example` содержит только пустые имена настроек.

Проверки: московская граница суток, D1 без незрелой когорты, дедупликация и конкуренция, разделение каналов/старых профилей, сохранение ресурсов при сбое аналитики, закрытый доступ API, отклонение произвольных диагностических полей, предел 20 событий, очистка старых подробностей без удаления прогресса, отсутствие секретных строк в собственных логах и копируемом тексте. Визуальная приёмка и запуск Telegram на телефоне отдельно; доступный ранее preview завершался `listen EPERM 127.0.0.1`.
