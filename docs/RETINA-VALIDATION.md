# Изображения для экранов 1× и 2×

8 ноября 2026, МСК.

Для всех 23 растровых исходников в public/art подготовлены 46 WebP-вариантов в public/art/retina. Это механический экспорт Lanczos3 с сохранением исходников и alpha-канала, а не нативная перерисовка высокого разрешения. 22 исходника увеличены при создании 2×; новые мелкие детали от этого не появляются. Попытка получить фон 2560×2560 через генератор вернула 1254×1254, поэтому её результат не выдаётся за нативный 2× и не подменяет сохранённый оригинал.

Размеры рассчитываются по одному кадру:
- сцены, галереи и реакции: 576 px для 1×, 1152 px для 2×;
- прозрачные кадры Чудика: 352 px для 1×, 704 px для 2×;
- сцене задан предел 480 CSS px; с запасом 4% по краям 2× покрывает отображаемую область;
- максимальная ширина прозрачного актёра — 68% сцены, с небольшим дыханием; 704 px покрывает её при 2×.

По требованию пользователя CSS и JS-предзагрузка всегда обращаются напрямую к @2x.webp. Выбор через image-set/devicePixelRatio удалён: Telegram WebView больше не может выбрать 1× по сообщённой плотности экрана. Это устраняет выбор меньшего варианта, но не доказывает причину каждого случая нечёткого изображения на телефоне. Шрифты WOFF2 и SVG-иконки не требуют растрового масштабирования. Исходные PNG/WebP остаются в проекте; интерфейс обращается к вариантам. Полный набор 1×/2× — 38 096 026 байт; он не загружается целиком при открытии острова. Однако 2×-атласы требуют больше памяти при декодировании, чем прежние исходники.

Воспроизведение экспорта: node scripts/export-art.mjs. Манифест фиксирует размеры исходников, сетки, размеры кадров, байты и признак увеличения.

Проверено: 46/46 файлов существуют, их фактические размеры совпадают с манифестом, сетки не нарушены, alpha-каналы сохранены. Все CSS-ссылки на изображения разрешаются. npm test — 15/15 (включая единый 2× URL для показа и предзагрузки всех иллюстраций); npm run typecheck — успешно. npm run build — успешно; наличие и размеры всех 46 файлов в dist/client проверены.

Ограничения: экспорт 2× не является восстановлением утраченной детализации. Retina-качество на реальном устройстве и расход памяти в Telegram не проверены; браузерная инфраструктура среды ранее завершилась с EPERM. Ручная проверка должна включать маленький экран, DPR 2/3, все вкладки, плавность реакции и устойчивость при переключении питомцев.
